# 手机 Chatbox 独立应用方案

> 目标：做一个**手机上独立安装运行的应用**，本身自带界面和数据，不依赖家里的电脑，也不需要把站点托管到网上。联网时直连 DeepSeek 官方 API。
> 本方案基于对现有源码的逐项摸底和网络实测，所有结论标注了依据来源。
> 编制日期：2026-11-23（2026-11-24 修订：TTS/ASR 纠正、应用定位修正）

---

## 一、先说结论

| 问题 | 结论 | 依据 |
|---|---|---|
| 手机能否直连 DeepSeek 对话 API？ | **能**，无需本机代理 | 实测 OPTIONS 预检返回 `access-control-allow-origin` 回显来源、`allow-methods: POST`、`allow-headers: authorization,content-type` |
| TTS / ASR 官方有没有？ | **有，我之前判断错了** | 官方文档：`POST /v1/tools/tts`（含 WebSocket 流式）、`POST /v1/tools/asr`；实测两个端点均放行 CORS。详见第七节更正 |
| 节假日 API 能否浏览器直连？ | **能** | 实测 `date.nager.at` 返回 `access-control-allow-origin: *` |
| 现在的应用能直接装到手机上吗？ | **不能** | 数据、API、工具、附件四项能力全压在 Node 服务端，手机端现在是「空壳」 |
| 这是不是一个「要托管的网站」？ | **不是** | 按你的定位：这是手机应用，前端资源打包进 App，数据存手机本地，无需静态托管 |
| 最大的坑是什么？ | 内置工具里有 4 个依赖系统能力（进程 / 网络探测 / 本机 IP），手机应用里无法实现 | `tools-core.cjs` 头部 require 了 `node:child_process`、`node:dns`、`node:net`、`node:os` |

**推荐路径**：先把应用改造成**自包含前端**（本地存储 + 直连官方 API + 工具移植 + Key 加密），再把整套前端资源打包成手机 App。电脑端现有服务端保持不变，两条线互不影响。

## 四、目标架构

```
手机 App（iOS / 安卓）
┌─────────────────────────────────────┐
│  自带的前端资源（打包进 App bundle） │
│  ├─ 界面（现有 public/ 基本不动）    │
│  ├─ IndexedDB   会话 / 设置 / 分组   │
│  ├─ IndexedDB   附件 Blob            │
│  ├─ Web Crypto  加密后的 API Key     │
│  └─ tools.js    可移植的内置工具     │
└──────────────────┬──────────────────┘
                   │ HTTPS（直连，无需服务器）
                   ▼
     api.deepseek.com（对话 / TTS / ASR / 模型 / 余额）
     节假日 API
```

手机端不经过任何自有服务器；电脑端现有服务端保持原样，供电脑浏览器继续使用。

## 五、分阶段改造清单

### 阶段 0：建立「存储抽象层」（不改行为，纯重构）

**目的**：把 `store.js` 里所有 `fetch('/api/...')` 收拢到一个适配器，之后切本地存储只换适配器实现，不动业务代码。

- 新建 `public/js/persistence.js`，导出统一接口：
  ```
  loadSnapshot() / saveSnapshot(snap) / patchSettings(p) / patchUi(p)
  putConversation(c) / deleteConversations(ids) / clearConversations()
  putGroup(g) / deleteGroup(id)
  saveAttachment(blob, filename) / getAttachment(id) / attachmentUrl(id)
  ```
- `serverAdapter`：现有 `fetch('/api/...')` 原样搬进去（供电脑端）。
- `localAdapter`（阶段 1 实现）：IndexedDB 版（供手机 App）。
- `store.js` 改为 `import * as db from './persistence.js'`，调用点替换为上述接口。
- 启动方式：手机 App 构建里注入 `window.__LOCAL_MODE__ = true`，或 URL 参数 `?local=1` 选择本地适配器。

**验收**：电脑端仍连原服务端时，全部功能与改造前一致（回归现有 11 个会话）。

### 阶段 1：本地存储（IndexedDB）

**新建 `public/js/local-store.js`**，手写约 40 行封装（不引外部依赖）。

数据库 `deepseek-chatbox`，object stores：

| store | key | 内容 |
|---|---|---|
| `kv` | 字符串 | `snapshot`（settings / ui / conversations / groups 合并对象）、`apiKeyEnc` |
| `attachments` | id | `{ id, filename, mime, blob, createdAt }` |

改造点：

- `loadSnapshot()`：首次打开 DB 为空 → 返回内置默认值（从 `DEFAULT_SETTINGS` 等常量构造），不再依赖服务端。
- `saveSnapshot()`：整对象 put 到 `kv`（数据量小，整存整取足够，参考原注释「单机单用户足够」）。
- `attachmentUrl(id)`：本地模式改为 `URL.createObjectURL(blob)`（`openAttachment` 等调用处需适配异步）。
- 附件上传：Blob 直接存 IndexedDB，不再发 HTTP。

**验收**：断网 + 关闭电脑，手机端能新建会话、发消息（mock 模式）、刷新后数据仍在。

### 阶段 2：API 直连（对话 / 模型 / 余额 / TTS / ASR）

**改 `public/js/api.js`**：

- `apiRoot()` 从 `/api/ds` 改为 `settings.baseUrl`（默认 `https://api.deepseek.com`）；mock 模式改为前端内置 mock 函数，去掉 `/api/mock` 依赖。
- `headers()` 从空对象改为 `{ Authorization: 'Bearer ' + key }`，key 从阶段 3 的加密存储读取。
- `streamChat()`：fetch 目标改直连，SSE 解析逻辑不变（CORS 已实测放行）。
- `listModels()` / `getBalance()`：改直连 `https://api.deepseek.com/models`、`/user/balance`。
- `synthesize()` / `transcribe()`：这两个端点**是官方的**（见第七节），直接把 `/api/ds` 前缀换成 `https://api.deepseek.com` 即可：
  - TTS：`POST https://api.deepseek.com/v1/tools/tts`（wav / pcm，音色 stella / tide）
  - ASR：`POST https://api.deepseek.com/v1/tools/asr`（multipart，16bit PCM WAV 或 Ogg Opus）
  - 两者实测均放行 CORS，无需降级、无需隐藏按钮。

**验收**：手机端真实 Key 直连，能流式对话、拉模型、查余额、语音合成与识别。

### 阶段 3：API Key 加密存储（按你的选择：存本机加密存储）

**安全事实须先说清**（不夸大）：前端没有「绝对安全」的 Key 存储。任何前端加密的密钥最终都落在设备上，能解开就说明本机也能解。正确做法是**提高门槛 + 限制暴露面**，而不是声称无法窃取。原生壳阶段可进一步用系统钥匙串（iOS Keychain）提升到硬件级保护。

方案：

- 首次进入让用户设置一个 6 位以上 **App PIN**（仅本地，不上传）。
- Web Crypto `PBKDF2(PIN, 随机 salt, 150000 次, SHA-256)` 派生 256-bit 密钥。
- `AES-GCM` 加密 API Key，密文 + salt + IV 存 IndexedDB 的 `kv.apiKeyEnc`。
- PIN 本身**不存储**；每次会话内解密一次，Key 只留内存。刷新后需重新输入 PIN。
- 提供「清除 Key」按钮，一键删除密文。

对应新增 `public/js/secure-key.js`，改 `settings.js` 增加 PIN 设置 / 解锁界面，`api.js` 的 `headers()` 从内存读 Key。

**验收**：IndexedDB 里看不到明文 Key；清除后无法调用 API；刷新需重新输 PIN。

### 阶段 4：内置工具取舍（40 个）

`tools-core.cjs` 依赖 `node:child_process` / `node:dns` / `node:net` / `node:os` / `node:fs` / `node:zlib`，无法整体搬进前端。分类处理：

| 类别 | 工具（据工具名与依赖推断，实施时逐个核对源码） | 处理 |
|---|---|---|
| A 纯计算，可直接移植 | calculator, hash_text, base64_codec, url_codec, json_format, text_stats, uuid_gen, random_pick, base_convert, percentage, date_diff, unit_convert, regex_test, diff_text, csv_json, slugify, password_gen, id_validator, timestamp_convert, json_minify, token_count, stat_calc, hex_view, color_convert, text_kit, qr_text（改为返回图片 Blob 而非写文件）, find_tool, current_time | 移到 `public/js/tools-browser.js`；`Buffer` 用 `Uint8Array`/TextEncoder 替换，`node:crypto` 用 Web Crypto 替换 |
| B 联网请求，受 CORS 限制 | web_search, fetch_url, http_request | 浏览器 fetch 只能访问**允许跨域**的站点；多数网页会失败。降级：保留但标注「可能失败」，失败给明确提示 |
| C 依赖数据，可移植 | get_balance, list_models（改直连官方 API）, search_history, usage_stats（改读 IndexedDB） | 数据源从服务端改为本地 / 官方 API |
| D 系统能力，手机端无法实现 | dns_lookup, port_check, local_ip, cmd_run | **从工具列表移除**（或置灰并说明「仅电脑版可用」） |

> 说明：A/B/C/D 分类依据工具名和文件头部依赖**推断**，实施前需逐个读实现确认；`qr_text`、`token_count` 我已读过源码确认依赖（`qr_text` 用 `fs.writeFileSync`，`token_count` 依赖 `tokenizer-core.cjs`）。

QR 实现（`qrMatrix` / `qrCapacity`，v1–40）是纯算法，可直接摘出复用，只需把 PNG 生成从 `Buffer` 改成 canvas / Blob。

**验收**：手机端工具列表里 D 类消失；A 类逐一跑通；B 类对允许跨域的站点可用，失败时有清晰提示。

### 阶段 5：打包成手机 App（自包含，无需托管）

前端改造成自包含后，整套资源打包进 App，不部署到任何服务器：

- **Android**：Capacitor / Cordova 把 `public/` 打进 WebView → APK，可直接安装。
- **iOS**：同一套前端用 Capacitor 生成 Xcode 工程 → GitHub Actions `macos-14` runner 云编译出 `.ipa`。
- WebView 加载**本地 bundle** 资源（`file://` 或 app 内 asset），不走网络取页面。
- 安装途径（iOS）：TrollStore（免签，iOS 14–16.6.1）/ Sideloadly（免费 Apple ID，7 天重签）/ 开发者账号。
- 必做自检：`CFBundleIdentifier`、`UILaunchScreen`、执行位 0755、用 `verify_ipa.py` 校验。

**验收**：手机装 App，断网能打开并看到本地历史会话；联网能直连官方 API 对话。

## 六、工作量与顺序建议

| 阶段 | 改动量 | 风险 | 是否可独立验收 |
|---|---|---|---|
| 0 存储抽象 | 中（改 store.js 约 15 处调用） | 低 | 是（回归电脑端） |
| 1 本地存储 | 中（新增 1 文件 + 适配器） | 中 | 是（断网可用） |
| 2 API 直连 | 小（改 api.js 数处） | 低（CORS 已实测） | 是（真实对话 + 语音） |
| 3 Key 加密 | 中（新增 secure-key.js + 设置 UI） | 中 | 是 |
| 4 工具取舍 | 大（40 个逐个核对移植） | 中高 | 是 |
| 5 App 打包 | 中（云编译配置 + 签名） | 中（签名 / 安装门槛） | 是 |

建议顺序：**0 → 2 → 3 → 1 → 5 → 4**。
理由：先打通「直连 + 加密 Key」让手机能真正对话，再补本地存储与打包出可安装 App；工具数量最多、最耗时，放最后且不影响主流程。

## 七、更正记录：TTS / ASR

我此前判断「DeepSeek 官方无 TTS/ASR 端点、手机端需降级」是**错误的**，在此更正。

**官方文档依据**：

| 能力 | 端点 | 说明 |
|---|---|---|
| TTS | `POST https://api.deepseek.com/v1/tools/tts` | 整段合成；也有 `wss://api.deepseek.com/v1/tools/tts` 做边生成边播；音色 stella（女）/ tide（男）；格式 wav / pcm；`filter_markdown` 默认 true |
| ASR | `POST https://api.deepseek.com/v1/tools/asr` | multipart `file` 字段；16bit PCM WAV 或 Ogg Opus；最大 8 MiB / 120 秒；返回 `{request_id, text, duration_ms}` |

来源：`https://api-docs.deepseek.com/zh-cn/api/tts`、`/zh-cn/api/asr`、`/zh-cn/guides/tts`、`/zh-cn/guides/asr`。

**CORS 实测**（2026-11-24，OPTIONS 预检）：

| 端点 | allow-origin | allow-methods | allow-headers |
|---|---|---|---|
| `/v1/tools/tts` | 回显来源 | POST | authorization, content-type |
| `/v1/tools/asr` | 回显来源 | POST | authorization, content-type |

结论：手机端**直接改域名直连即可，不降级、不隐藏按钮**。

## 八、风险与待确认项

1. **B 类联网工具**：受 CORS 限制，行为与电脑端不同，需接受降级。
2. **Key 安全**：前端加密只提高门槛，不能防本机取证；要真正安全需原生壳阶段接入 iOS Keychain。
3. **iOS 签名门槛**：本地打包和云编译可行，但装到真机需要 TrollStore / 自签 / 开发者账号，免费签名 7 天过期要重签。
4. **App 内存与存储**：WebView 内 IndexedDB 有配额上限，附件多时需提示用户清理。

**唯一待确认**：目标平台是 **iOS 单端**，还是 **iOS + Android 双端**？前端改造部分两者完全共用，只是阶段 5 的打包产物不同。
